mini_trading_system

아키텍처 & 폴더 구성

KIS 일봉을 TimescaleDB 에 쌓고(수집, 빨강) React 화면이 그 값을 읽는(조회, 파랑) 두 경로가 같은 DB 에서 만납니다. 아래는 그 흐름과, 실제로 커밋된 폴더 구성입니다.

01 데이터 흐름

수집(쓰기) · 조회(읽기) · best-effort(실패해도 무시) — 세 경로를 색으로 구분했습니다.

02 폴더 구성

실제 커밋된 파일 기준입니다. 배지는 역할을 가진 파일에만 붙였습니다.

backend/app/

FastAPI 서버 · 수집 로직

main.py
엔드포인트 전체. 매 요청마다 auth.require() 호출
auth.py
비밀번호 해시 · 세션 · PERMISSIONS 표
access_log.py
접근 로그에서 계좌번호 뒤 4자리만 남기고 가림
kis.py
앱키 → 토큰(캐시) → 일봉 · 거래일 캘린더 조회실전 예외
trading_calendar.py
거래일 계산기DB 없는 순수 함수
collection.py
증분 수집 로직. 버튼과 스케줄러가 똑같이 호출
scheduler.py
평일 16:00 KST 자동 수집lifespan
discord.py
수집 요약 전송best-effort
db.py
asyncpg 연결 풀
schemas.py
요청 · 응답 pydantic 모델

03 잊지 말아야 할 제약

위 다이어그램의 특정 경로에 걸려 있는 규칙만 추렸습니다. 전체는 CLAUDE.md 참고.

kis.py

앱키 · 토큰은 서버 밖으로 내보내지 않습니다. 화면엔 발급 여부 · 만료 시각 · 가려진 앞 4자리만.

KIS API 화살표

일봉은 모의 도메인, 거래일 캘린더만 실전 도메인(모의가 이 TR을 거절). 조회만 하고 주문은 안 냅니다.

discord.py

웹훅 URL 도 비밀입니다. 미설정 시 조용히 건너뛰고, 전송 실패도 수집 실패로 치지 않습니다.
